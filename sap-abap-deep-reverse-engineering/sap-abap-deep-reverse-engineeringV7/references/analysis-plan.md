# Analysis plan

## Purpose
Convert the selected profile into a transparent, bounded plan before full traversal.

## Required plan
`Objective | Root object | System/client | Source/version | Selected profile | Document intent | Critical tracks | Planned exclusions | Tool limitations | Expected deliverables | Estimated depth/nodes | Open decisions`

## Planning procedure
1. Use the preliminary assessment and selected profile.
2. Identify P0/P1 paths: writes, postings, locks, authorization-sensitive actions, dynamic dispatch, interfaces, critical configuration, and business-critical outputs.
3. List planned capability, process, entity, configuration, inbound, and impact work.
4. State unavailable capabilities such as live where-used or runtime execution.
5. Present the plan and allow one user scope adjustment.
6. Freeze scope and start the coverage registry.

Do not begin full analysis before the plan and intent are recorded. A plan is not a promise that unavailable evidence will be found.
