# Deliverable applicability

## Always required
Executive summary, scope/limitations, source context, profile/consumption, business and technical overview, findings/evidence, coverage/confidence, unresolved items, and validation summary.

## Conditional deliverables
- Entity catalog: persistent or material transient data exists.
- Configuration inventory: behavior is configuration-driven.
- State diagram: statuses and transitions exist.
- LUW diagram: writes, commits, rollback, update task, locks, or postings exist.
- Integration context: BAPI/RFC/API/IDoc/file/form/workflow/job exists.
- Authorization matrix: sensitive action/data or authorization path exists.
- Runtime handoff: a finding requires execution confirmation.
- Knowledge graph: requested or the scope spans several related artifacts.
- Migration section: replacement, conversion, or data movement is in scope.
- Performance section: high-volume or expensive paths are detected.

For each conditional deliverable record `Applicable`, `Not Applicable`, `Unavailable`, or `Out of Scope`, with reason. Never invent content to fill a template.
